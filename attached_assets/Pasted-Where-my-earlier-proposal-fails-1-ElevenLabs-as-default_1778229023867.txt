Where my earlier proposal fails
1. ElevenLabs as default voice = privacy & cost loss
Privacy: every utterance leaves the device, hits ElevenLabs servers (US), gets transcribed + synthesized + sometimes stored for abuse-monitoring. That directly contradicts your local-first ethos and the green/violet badge becomes mostly violet.
Cost: ElevenLabs Conversational AI is ~$0.08–0.15/min. A 10-min daily user = ~$30/mo per user. Brutal at scale.
Latency: WebRTC is great (~300ms), but you pay for it forever, on every turn.
2. "Provider toggle per mode" = decision fatigue
Asking users to pick text provider AND voice provider AND understand the tradeoffs is a power-user pattern. Most people will pick once, badly, and resent the chooser. A single "Privacy mode" switch (Local / Balanced / Best) that fans out to both is cleaner and easier to defend.

3. Combining voice+text in one thread sounds elegant but adds latency
Live STT streaming into a chat bubble means re-rendering on every partial transcript → React reconciliation cost on mobile, especially low-end Android. The thread should append on commit, not on partial. Show partials in a dedicated "live caption" strip above the input.

4. WebLLM (your roadmap) is the right call but I underweighted it
3B–8B quantized models run on phone WebGPU at ~20–40 tok/s
Zero per-request cost, zero network, zero leak
First load is ~1.5GB — painful but one-time, cacheable in OPFS
I should have led with this, not treated it as "Phase 2"
5. STT/TTS choice was lazy
Browser SpeechRecognition is not privacy-preserving on Chrome — it sends audio to Google. Only Safari does it on-device (and badly). I sold it as the "free local fallback" — that's wrong.

Revised architecture (honest tradeoffs)
Three privacy tiers, one switch
Tier	Text	STT	TTS	Latency	Cost/user/mo*	Privacy
Local 🟢	WebLLM (Llama-3.2-3B)	whisper.cpp WASM	Piper WASM / Web Speech (Safari only)	400-800ms TTFT	$0	All on-device
Balanced 🟡 (default)	Lovable AI Gemini Flash	Groq Whisper-large-v3	Piper WASM	200-400ms TTFT	~$0.50	Text leaves; voice synth local
Best 🟣	Lovable AI GPT-5	ElevenLabs Scribe realtime	ElevenLabs TTS	150-300ms	~$5-30	Everything cloud
* rough, 30 sessions/mo

Why this is better
Default = Balanced, not Best. Most users get Gemini Flash (already free via your gateway under quota) + local TTS. Voice never leaves their device for synthesis.
Groq for STT (not ElevenLabs realtime): Whisper-large-v3-turbo on Groq is ~$0.04/hr — 20× cheaper than ElevenLabs, comparable accuracy, sub-300ms.
Piper TTS in WASM for local voice. ~30MB model, runs on CPU, decent quality, zero cost, zero leak. Replaces my "browser SpeechSynthesis" suggestion which was inconsistent garbage.
WebLLM as a real Tier 1, not roadmap fluff. Ship the privacy mode toggle now even if Local is "coming soon" — sets the right product narrative.
No per-mode provider chooser. One switch, three named tiers, plain language ("Local • Private • Free" / "Balanced • Recommended" / "Best Quality • Cloud").
Latency wins I missed
Speculative streaming: start TTS on first sentence, not after full reply. Cuts perceived latency by 60-80%.
Optimistic UI: render the user's message instantly, show a shimmer placeholder for assistant before the network even responds.
No live transcript in thread: partial captions in a separate strip; commit to thread only on final. Saves ~50ms re-render on every word on a Pixel 6a.
Cost wins I missed
Cache TTS by hash of text: agent replies are often similar greetings/confirmations. CDN-cache common phrases → free playback.
Cap context window aggressively for the cheap tier (last 6 turns + summary). Gemini Flash with 100K context is overkill and you pay for the input tokens.
Local intent classifier decides if a query even needs the LLM (e.g. "what time is it" → built-in answer, no API call).
